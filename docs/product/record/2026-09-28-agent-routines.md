- 2026-09-28 — **A routine is now an assignment anyone can write, with no code, and what it may read is held for one run only.** A New Routine — a crew, a task, a schedule and a list of areas it may read — is created from the Mac (`POST /api/scheduled/routines`) and runs on the same scheduler as the product's routines, each run one crew run with the crew's own definition and the task appended. Its read grant never touches the crew's registry row: it rides on that run's queue row and is honoured only for the bearer minted for that run while the row runs, so before, after and on the crew's next run the area is unreadable — the ticket's test holds exactly that. Per-run grants are read-only by schema, per the owner's ruling: where a routine writes is its own ownership, never something a run is granted.

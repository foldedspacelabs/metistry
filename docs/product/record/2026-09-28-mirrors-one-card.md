- 2026-09-28 — **Needs You is one hub, not a pile of duplicates: one subject is one card with every asker on it, and a card the source settled says where.** An agent asking for a PR review and GitHub's own review request for the same PR are now a single card naming both askers — whichever arrived first — because every raise of a waiting subject lands on the same row (Postgres's unique index) and records its asker, once, rather than being dropped or doubled. When the source moves first — the review approved on GitHub, the PR merged, the Linear issue completed, the missing secret set — the card clears with a receipt (*You approved it on GitHub*), and the weekly review stops counting those as decisions the owner made. Issues assigned to the owner on GitHub now arrive as tasks the same way, and a missing secret's one request names everything that depends on it, not only what it has already stopped. Safe to leave running: the one-row guarantee and the receipt are written by core's one mirror path, a raise cannot forge an asker list or a receipt (refused), and a subject the owner answered is never re-asked while it lasts.

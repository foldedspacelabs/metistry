- 2026-09-28 — **A recorded meeting is answered on the Mac, or not at all.** While a capture session is in scope, the assistant's turn runs on the `private` tier, and that tier can only be a model on this machine: `metistry compute assign private` and the app's Compute pane refuse a cloud provider, and `compute.yaml` refuses one at load — so a hand edit, or repointing the provider later, fails the same way. The tier never falls back: not to the default model, which may be in the cloud or shadowed there, and not to the older `rules.yaml` tiers. With no private tier assigned, such a turn is refused with the one command that fixes it, rather than quietly answered off the machine. Enforced where the model is chosen, not by asking the assistant to be careful.

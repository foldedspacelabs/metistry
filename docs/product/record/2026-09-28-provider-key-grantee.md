- 2026-09-28 — **A provider's API key can reach only that provider, and only on the owner's say-so.** Until now the engine, the collectors, the router's scorer and the embedder each built their own `Authorization: Bearer …` and dialled whatever URL they had; nothing but each caller's care kept a key off another host, and `secrets.yaml` had no way to say "this key is for OpenRouter". Now a provider key has a grantee of its own (`provider:<name>`), and every compute call goes through one door in core that refuses any host but the provider's own and attaches the key itself — only while the owner's grant is On. The engine reads the grant on every call, so `metistry secrets grant <key> provider:<name> off` cuts it off on the next request with no restart. Under compose the containers get exactly one instance path, read-only: a directory holding only a copy of `secrets.yaml` (policy, never a value) that the reconciler keeps current every second — a directory rather than the file, because a single-file mount would keep a revoked grant alive until a restart. No install loses compute on the upgrade: `metistry update` grants each key `compute.yaml` already uses to its provider, once, and leaves any grant the owner wrote alone. Enforced at the tool, in the process that makes the call — the supervisor's egress proxy remains the second wall outside it.

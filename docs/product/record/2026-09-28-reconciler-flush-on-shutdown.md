- 2026-09-28 — **A write the reconciler accepted is now committed even when the reconciler is restarted a second later.** The commit queue lived in memory for a 30-second window and a stop discarded it, so every `metistry update` — which writes `metistry.lock` and `secrets.yaml` and then restarts the supervisor — left both files uncommitted for good, and "git is the record" quietly stopped holding for the two files that pin the install. The reconciler now commits its queue on SIGTERM before exiting, journals the queue under `.git/` so a hard kill loses nothing (the next start commits it under the principal and message it was written with, and touches nothing it did not queue itself), and `update` asks for the commit before it restarts anything. Safe to leave running because the recovery path can only commit what the bridge already accepted: every journal entry is re-checked against the bridge's own path rules, and a protected path is committed as `user` or not at all.

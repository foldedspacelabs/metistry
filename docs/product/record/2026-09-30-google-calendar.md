- 2026-09-30 — **Google Calendar invitations can be answered from Metistry, and what goes to Google is only the owner's own answer.** A Google Calendar connection signs in with Google through Metistry's own door — PKCE, a one-shot listener on 127.0.0.1, the refresh token in the instance's Keychain, the access token only in memory — with Metistry's public client id or the owner's own, so no user has to become a Google Cloud developer and nobody has to trust Metistry's client either. The reply is a PATCH whose body is exactly the owner's address and response with `attendeesOmitted`, and a test holds the wire to it; changes to the owner's own events touch only events nobody else is in; every change previews first and is refused if the event changed since. The sign-in's token may go to exactly two hosts — Google's token endpoint and the Calendar API — or the connection is not opened, and the calendar is read without ever asking for the description, the meeting link or the dial-in. There is still no door for a secret inside a URL: private ICS feeds stay out (ruled 2026-09-30).

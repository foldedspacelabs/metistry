- 2026-10-18 — **Connecting a dev tool is reversible, and an accidental revoke is recoverable.** `metistry connect --remove <tool>` revokes the tool's agent row first, then puts its config file back byte for byte (the first `connect` keeps a copy beside the file; removal restores it, or removes only its own entry if the owner has edited the file since, or deletes a file it created), then deletes the Keychain item — and running it twice changes nothing. Revoking used to be permanent, so reconnecting a tool meant a hand-named second agent; now `connect <tool>` on a revoked row registers it again under the same id, with a new token and none of what it held (grants, projects and autonomy return to default-deny, approved areas stay cleared), so provenance is kept and nothing widens by coming back. Only an external row can come back that way; the assistant's own row and a crew's still return only by their configuration. The test is the round trip: connect, remove, and the harness's config is the file the owner had.

- 2026-10-18 — **A connection's large answer no longer rides whole in an agent's context.** The Context Mode review (2026-10-04) found the one tool-output path Metistry owns — `connections_call` — returned upstream answers whole: one "GitHub Issues (20)" listing is 58.9 KB ≈ 14.7k tokens, carried in the caller's context and re-billed on every later turn, ≈69k input-token equivalents per occurrence by the review's model. The owner allowed folding (Q4) and X-132 ships it: over a threshold the owner sets, the answer is folded once, after redaction, as a **pure function of its text** — a listing to its first items, its last and a count; a log to its lines and counts; anything else to a head and a tail — so the same answer folds to the same bytes and a client's prompt cache keeps one stable prefix. The whole answer is kept for a day in a derived table keyed by the call's own `runs` row and paged back through the same tool (`page: "<handle>/<n>"`, no new tool, X-49), and the read is **enforced in SQL, not in a prompt**: `WHERE run_id = … AND principal = …`, so another agent presenting the handle hears the same `not_found` an unknown handle does, and nothing stored outlives its expiry. The owner turns it off per connection (`metistry connections policy <name> --fold off`) beside Allow · Ask First · Never, and every dialled call now records bytes in and bytes out, so the saving is a number on the audit row rather than a claim.

- 2026-10-18 — **Adding a phone starts with a code minted on the Mac, and the Mac refuses to mint one that cannot work.** `metistry enroll` (X-75) mints a single-use, ten-minute passkey enrolment code — stored hashed, printed once as the URL the phone opens — and `--cancel` kills an unused one the moment the owner is done with it, so a QR left on screen is already dead. No HTTP route mints a code, deliberately: shell access to this Mac is the root of trust for a first credential, and a test holds the client API table and the console's sources to that. Before it mints, the verb checks the origin the code is for and refuses by name when a phone could never complete the ceremony — the loopback address every install starts with, plain `http:`, an IP literal, or an address this Mac itself cannot reach or that answers as another instance — each refusal in its own words, naming `METISTRY_ORIGIN` and the fix, and writing nothing. The spender and both minters now share one implementation in core, so what the console accepts and what the Mac issues cannot drift apart; every mint and cancel is an audited `runs` row carrying the code's id, never the code.

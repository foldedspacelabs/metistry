- 2026-10-18 — **A phone added at one of this Mac's addresses signs in there, and a second address can now add one at all.** A passkey is scoped by the browser to the host it was created on and is never offered anywhere else; the console used to issue every ceremony the first configured origin's host, so an install reachable under two names — the remote-access name and the loopback one — could enrol a phone only at the first. Now each ceremony is issued for the origin the request came from, a request from an origin the owner never configured is refused on the spot with both sides named, and every passkey records the host it was created for (`passkeys.rp_id`, durable; the ones from before read as the first host, so no phone is stranded by the upgrade). Sign-in holds a passkey to its own host, not to the list: an assertion claiming a sibling host for a passkey that was never offered there — which no browser produces, and which a server must refuse anyway — is refused, naming the host it was added for. Devices now serves that host for every passkey, which is what a later pane needs to say *"Added for old.example.com. Remove it and add this phone again."* when the owner changes how the phone reaches the Mac. Tested with a software authenticator that can forge what Safari cannot.

- 2026-10-19 — **Two simultaneous Add to Today presses can no longer lose the capture's file — a real race in the capture tool, found by chasing a test flake rather than rerunning it (#549).** The capture tool named inbox files by the millisecond, so two attempts for one idempotency key inside the same millisecond chose the same path; when the later insert lost on the idempotency index it withdrew "its" file, which was the winner's, and the winning row survived pointing at nothing. The fix looks up the winning row first and removes the loser's file only when the winner does not name it. It is safe to leave running because it is held by a deterministic misuse test (both attempts share a pinned clock; the test fails without the fix and passes with it, and a second case keeps the old behaviour for a loser whose path differs) and by stress evidence on a scratch database: across three runs of 1000 iterations each, 142, 250 and 187 iterations lost the file before the fix on the natural clock (291, 381 and 223 with the clock pinned), and none of 1000 did after it, in any of three runs of either kind. The same naming collision under the vault sink, where a second same-millisecond put would throw instead of replaying, is recorded in the PR as noticed and left open.

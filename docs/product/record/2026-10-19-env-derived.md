- 2026-10-19 — **`.env` is derived, never hand-edited** (X-124; the owner's 2026-10-04 ruling that secrets, the Keychain and `.env` were "too much cognitive load", reversing M7). `metistry up` now writes `.metistry/state/.env` from `.metistry/*.yaml` and the login Keychain — once per run, after every mint and before compose or a launchd job reads it — under a header carrying the sha256 of its body, and renders the jobs from the same values, so the file and the plists cannot disagree (the 0.14.2 drift). Two renders from the same yaml and Keychain are byte-identical: three sections, each sorted, and no timestamp. The migration loses nothing by construction: every secret-shaped line a hand-written file held is adopted into this instance's Keychain (never minted over), every other line is carried by name until a `.metistry/*.yaml` key owns it, a value the yaml now decides is named as superseded, and the file as it was is kept beside the render as `.env.pre-render` (0600). A hand edit is a code path, not a warning: doctor's new `env` row names the changed, added and removed lines from a record of names and line hashes (never a value), and the next `up` adopts an edited secret into the Keychain, keeps an edited configuration line, brings back a removed line a store still holds, and says what it did with each. Safe to leave running because the render is idempotent, reads the Keychain through the same stdin-only `security` seam, and every writer of the file is this CLI — which re-stamps what it writes, so only a hand reaches `hand-edited`.

- 2026-10-19 — **How your phone reaches this Mac is now a recorded choice, and a tunnel at the console's front door is no longer a working configuration.** Every install starts at None: nothing exposed, the console's origin list is the loopback address alone, and Add a Phone says so and names Settings ▸ Remote Access. The choice lives in the instance's `deployment.yaml` as a `remote:` block the owner's hand writes through the protected write — the provider, its mode, the address it yields and non-secret settings, never a credential — and `metistry up` derives the console's origins from that record rather than from whatever was typed into `.env`: the provider's address first (so adding a phone mints for it with no change anywhere else), the loopback address second, and with None the loopback address alone. A remote address someone had written into `.env` by hand is dropped and named in the plan, because that hand-written address with a tunnel pointed at the console's main port is exactly the gap the proxy listener closed — the main port honours this Mac's owner token for anything the tunnel carries. Changing provider follows one rule, tested with a stand-in adapter so every real one inherits it: configure the new one, wait until its address answers from this Mac, write the record, and only then undo the old — a set-up that fails writes nothing, an address that never answers undoes nothing, and the phone is never left with nothing mid-change. A provider's pasted token is read from stdin or a hidden prompt and refused, unrepeated, if it arrives as an argument. Doctor fails any provider forwarding to the main port by name, and passes None.
